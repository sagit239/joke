# MILESTONES — פיתוח האפליקציה ליצירת בדיחות

## בסיס התכנון

המסמך מבוסס על [PRD.md](PRD.md), [ARCHITECTURE.md](ARCHITECTURE.md) ו־[DESIGN.md](DESIGN.md). הפיתוח מחולק לחמש אבני דרך עוקבות: תשתית הכרחית, יצירת בדיחה בטוחה מקצה לקצה, התאוששות מכשלים, התקנה כ־PWA ופריסה ל־Production.

- קיים מסך מוצר אחד: מסך יצירת בדיחה. מצבי המתנה, תוצאה, דחייה ושגיאה שייכים אליו.
- בחירת המודל היא `gpt-6-luna`, בהתאם להבהרה המאושרת המתועדת ב־ARCHITECTURE.md, המחליפה את אזכור GPT-5 ב־PRD המקורי.
- אין Database, Authentication, היסטוריה או אחסון תוכן מתמשך. אין הקמת Supabase או Database Migrations באף אבן דרך.
- ברירות המחדל הטכניות, העיצוב והנוסחים נלקחים ממסמכי המקור. אין להוסיף יכולות כדי להשלים אבן דרך.
- לכל אבן דרך יש תוצר עצמאי לבדיקה, אך גרסאות ביניים אינן מיועדות להפעלה ציבורית לקהל ילדים. תנאי ההפעלה הציבורית שבארכיטקטורה נבדקים לפני השקת Production.

## Milestone 1 — בסיס הפרויקט וסביבת בדיקה

**מטרה:** להקים פרויקט שניתן להריץ ולפרוס לבדיקה, עם הפרדה מאומתת בין הדפדפן לשרת. זהו תנאי טכני מקדים ליכולות המשתמש.

### מה יש לממש

- פרויקט Next.js 16 עם App Router, TypeScript strict, React תואם, Node.js 24 ו־CSS Modules. לקבע תלויות ב־Lockfile.
- Git Repository יחיד ב־GitHub וחיבור לפרויקט Vercel, עם Preview לענפי עבודה ו־main כ־Production Branch.
- מעטפת המסך היחיד עם עברית ו־RTL, מבנה הטופס ואזור התוכן לפי DESIGN.md. אין צורך להשלים כאן את כל הליטוש החזותי.
- שלד `POST /api/joke`, חוזי Request/Response והפרדה ל־API Boundary, Joke Service ו־OpenAI Adapter המסומן server-only.
- Configuration לסביבות Development, Preview ו־Production: קובץ .env.example ללא סודות, החרגת .env.local והפרדת מפתחות. המשתמש יגדיר פרטי חשבון וסודות בממשקי השירותים בהדרכה; אין לבקש הדבקת API Key בשיחה.
- Build אוטומטי הכולל Type Checking ובדיקות חוזה ראשוניות עם Mocks. אין קריאות AI אמיתיות ב־CI.
- להשאיר יצירה כבויה בסביבות ציבוריות באמצעות `GENERATION_ENABLED=false` עד לשלב המתאים. אין להציג בדיחה קבועה כאילו נוצרה ב־AI.

### תוצר מצופה

פרויקט רץ מקומית ו־Preview נגיש ב־HTTPS, המציג את מעטפת המסך בעברית. ה־API מחזיר באופן מבוקר `SERVICE_UNAVAILABLE` כאשר היצירה כבויה. זהו שלד לבדיקה, ולא גרסה מלאה של יכולת היצירה.

### Definition of Done

- [ ] התקנה נקייה באמצעות `npm ci`, בדיקות ה־Build ו־`next build` מסתיימות בהצלחה.
- [ ] Push לענף עבודה יוצר Preview באופן אוטומטי; מתועדים הקישור והגרסה שנפרסה.
- [ ] המבנה כולל כותרת, Label, שדה, לחצן ואזור תוכן יחיד, ללא מסכים או רכיבי ניווט נוספים.
- [ ] `GENERATION_ENABLED=false` מונע קריאה לספק, והלקוח מציג את הודעת הכשל המאושרת ללא Stack Trace.
- [ ] אין מפתח ב־Repository, ב־Client Bundle או בתגובות HTTP; הגדרות Production אינן מועתקות לפיתוח או ל־Preview.
- [ ] ניתן להסביר ולהדגים אילו חלקים הם שלד ואילו בדיקות משתמשות ב־Mocks.

## Milestone 2 — יצירת בדיחה בטוחה מקצה לקצה

**מטרה:** לאפשר למשתמש להזין נושא או להשאירו ריק, לקבל בדיחה בעברית וליצור נוספת, עם מסנני התוכן לפני הצגתה.

**תלות:** אישור השלמת Milestone 1. לבדיקות חיות נדרשים מפתח Development תקין וגישה למודל הנבחר; משתמשים בקלט סינתטי בלבד.

### מה יש לממש

- הטופס המעוצב במלואו לפי DESIGN.md וה־Mockup: Rubik ו־Heebo, צבעי HEX שהוגדרו, קווי מתאר, פינות מעוגלות וצללים קשיחים.
- שליחה מהלקוח ל־Backend באותו Origin, נרמול trim ו־NFC וטיפול בנושא ריק או ברווחים בלבד.
- Validation ובקרות הכניסה שהוגדרו בארכיטקטורה, כולל Origin, סוג תוכן, Body עד 4 KiB ונושא עד 200 Unicode Code Points.
- OpenAI SDK בשרת בלבד, Responses API עם Structured Outputs והגדרות המודל שנבחרו; ללא שיחה מתמשכת וללא Streaming.
- שרשרת הסינון השלמה: Moderation לקלט שאינו ריק, החלטת התאמת נושא ויצירה, Moderation לפלט ובדיקה נפרדת של התאמה למשפחה, עברית ורלוונטיות.
- State של המתנה, הצלחה ודחייה. בזמן הבקשה מוצגת „מכינים לכם בדיחה…” ונמנעת שליחה כפולה; התיבה מושבתת לפי הארכיטקטורה.
- הצגת בדיחה מאושרת אחת בלבד. בקשה חדשה משתמשת בנושא הנוכחי ומחליפה את הקודמת. אין שמירה או Cache לתוצאות.
- דחיית נושא מציגה „בחרו נושא שמתאים לכל המשפחה”, ללא בדיחה חלופית. כשל בסינון חוסם תוצאה ומציג את הודעת הכשל.

### תוצר מצופה

גרסת Development עובדת של מסך יצירת הבדיחה, בעיצוב המוגדר, שמייצרת תוצאות אמיתיות דרך ה־Backend ומציגה אותן רק לאחר הסינון. ניתן לבדוק את אותה הזרימה ב־Preview מורשה עם מפתח פיתוח מוגבל.

### Definition of Done

- [ ] „כלבים” מחזיר בדיחה בעברית הקשורה לכלבים; נושא בשפה אחרת מחזיר בדיחה בעברית הקשורה לנושא.
- [ ] נושא ריק ורווחים בלבד מפיקים בדיחה כללית, ללא שגיאת שדה חובה.
- [ ] לחיצה חוזרת אחרי סיום מפעילה בקשה חדשה; לחיצה כפולה בזמן המתנה מפעילה בקשה אחת בלבד. אין דרישה להבטיח ייחודיות טקסטואלית.
- [ ] נושא שנדחה מציג את ההודעה שנקבעה, ללא תוכן אסור וללא החלפתו בנושא אחר.
- [ ] בדיקות עם Mocks מוכיחות שפלט אינו נשלח ללקוח לפני שכל בדיקות התוכן אישרו אותו; פלט אסור, סירוב בבדיקת הפלט או בדיקה שנכשלה אינם מוצגים.
- [ ] נבדקים קלטי Prompt Injection ודוגמאות לכל קטגוריית תוכן אסורה ב־PRD. תוצאות הבדיקה מתועדות, ללא טענה להבטחת סינון מוחלטת.
- [ ] ממשק ה־API אוכף Validation לפי החוזה, וכל תגובותיו כוללות `Cache-Control: no-store`.
- [ ] הדפדפן פונה רק ל־API האפליקציה; כל פניות OpenAI מתבצעות בשרת. לוגים אינם כוללים נושא, בדיחה או Secrets.
- [ ] השוואה חזותית ל־Mockup מאשרת מבנה, היררכיה, צבעים ו־RTL. נתוני ההמחשה מהתמונה אינם מקובעים כברירת מחדל.
- [ ] בדיקות ה־Build עוברות; בדיקות AI חיות ותוצאותיהן מסומנות בנפרד מבדיקות עם Mocks.

## Milestone 3 — התאוששות מכשלים ושימוש אמין

**מטרה:** להשלים את יכולת המשתמש לחזור לפעולה לאחר כשל, ללא תקיעה במצב המתנה או חשיפת תוכן ופרטי שרת.

**תלות:** אישור השלמת Milestone 2.

### מה יש לממש

- מיפוי מלא של שגיאות לפי API Contract, כולל תגובות ספק, פלט פגום או שנקטע, כשל Validation, מכסה ו־Rate Limit.
- Deadline משותף של 45 שניות, `maxDuration=60` ו־Client Timeout של 55 שניות, בהתאם לערכי ההתחלה בארכיטקטורה.
- `maxRetries: 0` וללא Retry אוטומטי בלקוח, ללא יצירה מחדש אחרי פסילת תוכן.
- טיפול בכשל HTTP שאינו JSON, ב־Timeout של הפלטפורמה ובאובדן רשת.
- שחרור מצב ההמתנה ושמירת הנושא ב־State כדי שהמשתמש יוכל לנסות שוב. הודעת הכשל היא „לא הצלחנו ליצור בדיחה. נסו שוב”.
- אימות הצגת תוצאה כטקסט בלבד, ללא HTML פעיל, ונגישות הטופס והודעות המצב: Label, Focus נראה ו־aria-live.

### תוצר מצופה

אותה יכולת יצירה עובדת גם לאחר שגיאות ותקלות מדומות, עם תגובות צפויות ואפשרות ניסיון נוסף באותו מסך.

### Definition of Done

- [ ] בדיקות מדומות מכסות פלט ריק, JSON פגום, Incomplete, Safety Refusal ושגיאות ספק 401, 429 ו־5xx, לפי המיפוי שבארכיטקטורה.
- [ ] ניתוק רשת, תגובת HTML במקום JSON וחריגה מה־Deadline אינם משאירים את המסך ב־loading ואינם מציגים פרטי תקלה פנימיים.
- [ ] אחרי כשל התיבה והלחצן חוזרים לשימוש, הנושא נשמר וניסיון נוסף יכול להצליח.
- [ ] ספירת הקריאות בבדיקות מאשרת שאין Retry סמוי או בקשה כפולה, ושכשל בבדיקת תוכן אינו מפעיל יצירה אוטומטית נוספת.
- [ ] טקסט שנראה כ־HTML מוצג כטקסט ואינו מתבצע בדפדפן.
- [ ] ניתן להשלים את הפעולה עם מקלדת, לזהות Focus ולקבל הודעות מצב באמצעות מנגנון aria-live, ללא הוספת Toast או מסך שגיאה.
- [ ] רענון מאפס נושא ובדיחה; אין שמירתם ב־localStorage, ב־sessionStorage, ב־IndexedDB או בקובצי שרת.
- [ ] בדיקות Regression של מסלולי Milestone 2 ובדיקות ה־Build עוברות.

## Milestone 4 — התקנה ושימוש במובייל כ־PWA

**מטרה:** לאפשר למשתמש להתקין את האתר במכשיר תומך וליצור בדיחות מתוך ה־PWA, באותו מסך ובאותו עיצוב.

**תלות:** אישור השלמת Milestone 3 ו־Preview מורשה ב־HTTPS המתאים לבדיקת התקנה.

### מה יש לממש

- Web App Manifest עם start_url ו־scope ל־`/`, מצב standalone, עברית ו־RTL, אייקונים בגדלים 192×192 ו־512×512 ו־apple-touch-icon.
- שם התקנה „בדיחות”, כהנחת המימוש הקיימת בארכיטקטורה עד לבחירת שם מוצר אחר.
- התקנה באמצעות הדפדפן, ללא מסך התקנה או כפתור חדש באפליקציה, וללא Service Worker, Offline Cache או Background Sync.
- התאמות Responsive הנדרשות לשמירת טור תוכן קריא, שבירת טקסט טבעית ואזור מגע בגובה של לפחות 48px, בהתאם ל־DESIGN.md.

### תוצר מצופה

PWA שניתן להתקין ולפתוח במכשירי בדיקה תומכים, עם יצירת בדיחות עובדת בחיבור לאינטרנט.

### Definition of Done

- [ ] ה־Manifest והאייקונים נטענים בהצלחה, ללא קישורים שבורים, והאתר מוגש ב־HTTPS.
- [ ] נבדקות התקנה ופתיחה ב־Chrome על Android וב־Safari על iOS, בהתאם ליעדי האימות שבארכיטקטורה. מתועדים המכשיר, הדפדפן והתוצאה.
- [ ] פתיחה מהאייקון מציגה את מסך היצירה, וניתן להשלים יצירה לפי נושא ויצירה כללית דרך ה־Backend.
- [ ] אין גלילה אופקית או חיתוך של שדה, לחצן ובדיחה במידות מובייל שנבדקו; תוכן ארוך נשבר באופן קריא.
- [ ] אין הקשחה של העמוד ליחס Smartphone או מסגרת מכשיר דקורטיבית מתוך תמונת ה־Mockup.
- [ ] אין יצירה ללא רשת, אגירת בקשות או שימוש בבדיחה שמורה כתחליף. כשל רשת מטופל כבאבן הדרך הקודמת; אין דרישה לטעינת האתר Offline.
- [ ] בדיקות ה־Build ו־Regression עוברות. בדיקה שלא בוצעה במכשיר יעד מסומנת כחסרה ואינה נחשבת הצלחה.

## Milestone 5 — פריסה מאובטחת ל־Production ואימות מסירה

**מטרה:** להפעיל את המוצר המלא בכתובת ציבורית, עם הפרדת סביבות, הגנות התשתית ותהליך עדכון אוטומטי מ־GitHub.

**תלות:** אישור השלמת Milestone 4, זמינות חשבונות השירות והשלמת תנאי ההפעלה הציבורית שב־ARCHITECTURE.md.

### מה יש לממש

- להשלים Configuration ייעודי ל־Production ב־Vercel: מפתח OpenAI נפרד הנשמר רק בשירות, מודל, APP_ORIGIN ו־GENERATION_ENABLED.
- לוודא שהשימוש מתאים לתוכנית Vercel שנבחרה ולמכסות השירותים. אין לבצע שדרוג או התחייבות כספית ללא אישור המשתמש.
- לאמת ולהסדיר עם המשתמש את תלות ZDR בפרויקט OpenAI ובמודל, בהתאם לארכיטקטורה ולקהל הכולל ילדים. אין להציג `store:false` כהוכחה ל־ZDR.
- להגדיר WAF Rate Limiting ל־POST /api/joke לפי ברירת המחדל התכנונית של 10 בקשות לדקה לפי IP, ולהגדיר את Security Headers שנקבעו.
- לאמת Build ופריסה אוטומטיים מ־main, סודות נפרדים ל־Preview ול־Production והעדר Secrets ב־Preview לא מהימן.
- לבצע Smoke Test ב־Production ולאמת נוהל Rollback לגרסה קודמת. אין Database Migrations.

### תוצר מצופה

אתר ו־PWA פעילים ב־Production, עם היכולת המלאה, הגנות התשתית ופריסה אוטומטית לעדכונים. אם תלות ספק נדרשת לא הוסדרה, היצירה הציבורית נשארת כבויה ואבן הדרך אינה מסומנת כהושלמה.

### Definition of Done

- [ ] תנאי הפרטיות והספק הנדרשים בארכיטקטורה אומתו ומתועדים, כולל מצב ZDR עבור הפרויקט והמודל; אין הסתמכות על הנחה שלא אושרה אצל הספק.
- [ ] גרסת Production נפרסת אוטומטית מ־main רק לאחר מעבר בדיקות ה־Build. מתועדים URL ומזהה הגרסה.
- [ ] מפתח Production נשמר רק ב־Vercel ואינו מופיע במחשב הפיתוח, ב־GitHub, ב־Client Bundle, בתגובות או בלוגים.
- [ ] Smoke Test בקלט סינתטי מאשר יצירה לפי נושא, יצירה כללית, החלפת בדיחה ודחיית נושא לא מתאים; נבדקת גם יצירה מתוך ה־PWA בכתובת Production.
- [ ] כלל WAF חוסם חריגה לפני קריאה לספק; הלקוח מציג הודעת כשל מאושרת גם כאשר תגובת החסימה אינה JSON. בדיקת החריגה מבוקרת ואינה בדיקת עומס בלתי מוגבלת.
- [ ] Origin בלתי מורשה נדחה; HTTPS ו־Security Headers פועלים ללא שבירת הטופס או ה־PWA.
- [ ] `GENERATION_ENABLED=false` עוצר יצירה לאחר החלת התצורה בפריסה חדשה; שינויי Environment Variables אינם נחשבים פעילים לפני Deployment מתאים.
- [ ] מתועדים אופן Rollback ומגבלתו: החזרת קוד אינה משחזרת בהכרח WAF, Secrets או הגדרות OpenAI.
- [ ] המשתמש מקבל את כתובת האתר, תוצאות הבדיקות, מגבלות ידועות והנחיה ברורה לעדכון דרך GitHub. אין בדיקות חסרות המוצגות כאילו עברו.

## Development Execution Rules — כללי ביצוע הפיתוח

ההנחיות הבאות מחייבות את ה־AI שיבצע את הפיתוח:

1. יש לפתח את ה־Milestones לפי הסדר שהוגדר במסמך, ולהשלים את ה־Definition of Done של כל אחד מהם לפני המעבר לבא אחריו.
2. לאחר השלמת כל Milestone, יש לעצור את הפיתוח ולהציג למשתמש את התוצר שהושלם, קישור או דרך להפעלתו, ואת תוצאות הבדיקות מול כל תנאי ב־Definition of Done.
3. יש להבחין בדיווח בין בדיקות עם Mocks, בדיקות AI חיות ובדיקות במכשירים אמיתיים. יש לסמן במפורש בדיקה שלא בוצעה, כשל או תלות חיצונית שלא הוסדרה. אבן דרך עם תנאי חובה חסר אינה נחשבת שלמה.
4. אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש. אישור להתחיל או להשלים את אבן הדרך הנוכחית אינו אישור להמשיך אוטומטית לבאה.
5. אין לעקוף תלות חסרה באמצעות שינוי פיצ'רים, החלפת שירותים או הקלה בדרישות התוכן והפרטיות. יש להציג את החסם ולבקש הבהרה כאשר נדרשת הכרעת משתמש.
6. פריסה ציבורית עם יצירה פעילה מתבצעת רק במסגרת Milestone 5 ולאחר אישור להתחילו והשלמת תנאי ההפעלה. חיבור GitHub ב־Milestone 1 אינו אישור להפעיל יצירה ציבורית במהלך הפיתוח.

מסמך זה מגדיר את תוכנית הפיתוח בלבד; עצם יצירתו אינה מתחילה את Milestone 1.

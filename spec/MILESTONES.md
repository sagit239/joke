# MILESTONES — פיתוח האפליקציה ליצירת בדיחות

## בסיס התכנון

המסמך מבוסס על [PRD.md](PRD.md), [ARCHITECTURE.md](ARCHITECTURE.md) ו־[DESIGN.md](DESIGN.md). הפיתוח מחולק לחמש אבני דרך עוקבות: תשתית מקומית, יצירת בדיחה בטוחה מקצה לקצה, התאוששות מכשלים, פריסה ל־Production, והתקנה כ־PWA.

- קיים מסך מוצר אחד: מסך יצירת בדיחה. מצבי הפתיחה („בדיחה יומית”), המתנה, תוצאה, דחייה ושגיאה שייכים אליו, וכל הודעות המצב מוצגות בתוך כרטיס התוצאה.
- המודל נקרא מההגדרה `OPENAI_MODEL`, עם ברירת המחדל `gpt-6-luna` (ADR-1).
- אין Database, Authentication, היסטוריה או אחסון תוכן מתמשך. אין הקמת Supabase או Database Migrations באף אבן דרך.
- ללא תשלום חדש: Vercel Hobby בלבד, ו־OpenAI ביתרה הקיימת, עם טעינה אוטומטית כבויה (ADR-3).
- ברירות המחדל הטכניות, העיצוב והנוסחים נלקחים ממסמכי המקור. אין להוסיף יכולות כדי להשלים אבן דרך.
- Milestones 1–3 נבנים ונבדקים מקומית בלבד. הדחיפה לגיטהאב בסופם אינה מפרסמת דבר, כי Vercel מחובר רק ב־Milestone 4 (ADR-5).

## Milestone 1 — בסיס הפרויקט והרצה מקומית ✅

**מטרה:** להקים פרויקט שרץ מקומית, עם מעטפת המסך והפרדה מאומתת בין הדפדפן לשרת. זהו תנאי טכני מקדים ליכולות המשתמש.

### מה יש לממש

- פרויקט Next.js 16 עם App Router, TypeScript strict, React תואם, Node.js 24 ו־CSS Modules. לקבע תלויות ב־Lockfile.
- מעטפת המסך היחיד עם עברית ו־RTL, כותרת הלשונית „בדיחה לפי נושא”, ומבנה הטופס ואזור התוכן לפי DESIGN.md: כותרת, Label, שדה, לחצן, כותרת „בדיחה יומית” וכרטיס ריק. אין צורך להשלים כאן את כל הליטוש החזותי.
- טופס שבו Enter בשדה ולחיצה על הלחצן מפעילים את אותה שליחה.
- שלד `POST /api/joke`, חוזי Request/Response והפרדה ל־API Boundary, Joke Service ו־OpenAI Adapter המסומן server-only.
- קובץ `.env.example` עם שמות המשתנים בלבד (`OPENAI_API_KEY`, `OPENAI_MODEL`, `GENERATION_ENABLED`), והעתקה חד־פעמית שלו ל־`.env`. המשתמש ממלא את הערכים בעצמו; אין לבקש הדבקת API Key בשיחה.
- Vitest ופקודה `npm run check` הכוללת Type Checking, בדיקות חוזה ראשוניות עם Mocks ו־`next build`. אין קריאות AI אמיתיות בבדיקות.
- היצירה עדיין לא ממומשת: ה־API מחזיר `SERVICE_UNAVAILABLE`, והלקוח מציג בכרטיס את הודעת הכשל. אין להציג בדיחה קבועה כאילו נוצרה ב־AI.
- למלא ב־CLAUDE.md את פקודות ההרצה והבדיקות.

### תוצר מצופה

פרויקט שרץ מקומית ומציג את מעטפת המסך בעברית. לחיצה על הלחצן מציגה „מכינים לכם בדיחה…” ואז את הודעת הכשל המאושרת. זהו שלד לבדיקה, ולא גרסה מלאה של יכולת היצירה.

### Definition of Done

- [ ] התקנה נקייה באמצעות `npm ci`, ו־`npm run check` מסתיים בהצלחה.
- [ ] האפליקציה רצה מקומית ונפתחת בדפדפן.
- [ ] המבנה כולל כותרת, Label, שדה, לחצן, כותרת „בדיחה יומית” וכרטיס ריק, ללא מסכים או רכיבי ניווט נוספים.
- [ ] לחיצה על הלחצן או על Enter מציגה בכרטיס את הודעת ההמתנה ואז את הודעת הכשל המאושרת, ללא Stack Trace.
- [ ] אין מפתח ב־Repository, ב־Client Bundle או בתגובות HTTP; `.env` אינו נכלל ב־Git.
- [ ] ניתן להסביר ולהדגים אילו חלקים הם שלד ואילו בדיקות משתמשות ב־Mocks.

## Milestone 2 — יצירת בדיחה בטוחה מקצה לקצה ✅

**מטרה:** לאפשר למשתמש להזין נושא או להשאירו ריק, לקבל בדיחה בעברית וליצור נוספת, עם מסנני התוכן לפני הצגתה.

**תלות:** אישור השלמת Milestone 1. נדרשים מפתח Development בקובץ `.env`, יתרה בחשבון OpenAI עם טעינה אוטומטית כבויה, וגישה למודל שנבחר (מאומתת בתחילת אבן הדרך, ADR-1); משתמשים בקלט סינתטי בלבד.

### מה יש לממש

- הטופס המעוצב במלואו לפי DESIGN.md וה־Mockup: Rubik ו־Heebo, צבעי HEX שהוגדרו, קווי מתאר, פינות מעוגלות, צללים קשיחים, רוחב מקסימלי של 480px, מצב מושבת ו־Focus.
- שליחה מהלקוח ל־Backend באותו Origin, נרמול trim ו־NFC וטיפול בנושא ריק או ברווחים בלבד.
- Validation ובקרות הכניסה שהוגדרו בארכיטקטורה, כולל בדיקת Same-Origin, סוג תוכן, Body עד 4 KiB ונושא עד 200 Unicode Code Points.
- OpenAI SDK בשרת בלבד, Responses API עם Structured Outputs והגדרות המודל שנבחרו; ללא שיחה מתמשכת וללא Streaming.
- שרשרת הסינון לפי ARCHITECTURE.md 2.6: Moderation לקלט שאינו ריק, קריאת יצירה אחת שמכריעה גם על התאמת הנושא, בדיקות שרת לפלט (לא ריק, בעברית, עד 600 תווים) ו־Moderation לפלט.
- State של פתיחה, המתנה, הצלחה ודחייה, עם החלפת הכותרת ל־„הבדיחה שלכם” אחרי הבדיחה הראשונה. בזמן הבקשה מוצגת בכרטיס „מכינים לכם בדיחה…” ונמנעת שליחה כפולה; התיבה מושבתת.
- הצגת בדיחה מאושרת אחת בלבד, עם שבירות השורה שלה. בקשה חדשה משתמשת בנושא הנוכחי ומחליפה את הקודמת. אין שמירה או Cache לתוצאות.
- דחיית נושא מציגה בכרטיס „בחרו נושא שמתאים לכל המשפחה”, ללא בדיחה חלופית. כשל בסינון חוסם תוצאה ומציג את הודעת הכשל.

### תוצר מצופה

גרסה מקומית עובדת של מסך יצירת הבדיחה, בעיצוב המוגדר, שמייצרת תוצאות אמיתיות דרך ה־Backend ומציגה אותן רק לאחר הסינון.

### Definition of Done

- [ ] „כלבים” מחזיר בדיחה בעברית הקשורה לכלבים; נושא בשפה אחרת מחזיר בדיחה בעברית הקשורה לנושא.
- [ ] נושא ריק ורווחים בלבד מפיקים בדיחה כללית, ללא שגיאת שדה חובה.
- [ ] לפני הבדיחה הראשונה מוצגת „בדיחה יומית” מעל כרטיס ריק; אחריה „הבדיחה שלכם”.
- [ ] לחיצה חוזרת או Enter אחרי סיום מפעילים בקשה חדשה; לחיצה כפולה בזמן המתנה מפעילה בקשה אחת בלבד. אין דרישה להבטיח ייחודיות טקסטואלית.
- [ ] כל הנושאים בעמודת „לא מתאים” שבטבלת הנושאים ב־PRD מציגים את הודעת הדחייה, וכל הנושאים בעמודת „מתאים” מחזירים בדיחה. תוצאות הנושאים הגבוליים מתועדות.
- [ ] בדיקות עם Mocks מוכיחות שפלט אינו נשלח ללקוח לפני שכל בדיקות התוכן אישרו אותו; פלט אסור או בדיקה שנכשלה אינם מוצגים.
- [ ] נבדקים קלטי Prompt Injection. תוצאות הבדיקה מתועדות, ללא טענה להבטחת סינון מוחלטת.
- [ ] ממשק ה־API אוכף Validation לפי החוזה, וכל תגובותיו כוללות `Cache-Control: no-store`.
- [ ] הדפדפן פונה רק ל־API האפליקציה; כל פניות OpenAI מתבצעות בשרת. לוגים אינם כוללים נושא, בדיחה או Secrets.
- [ ] השוואה חזותית ל־Mockup מאשרת מבנה, היררכיה, צבעים ו־RTL. נתוני ההמחשה מהתמונה אינם מקובעים כברירת מחדל.
- [ ] `npm run check` עובר; בדיקות AI חיות ותוצאותיהן מסומנות בנפרד מבדיקות עם Mocks.

## Milestone 3 — התאוששות מכשלים ושימוש אמין

**מטרה:** להשלים את יכולת המשתמש לחזור לפעולה לאחר כשל, ללא תקיעה במצב המתנה או חשיפת תוכן ופרטי שרת.

**תלות:** אישור השלמת Milestone 2.

### מה יש לממש

- מיפוי מלא של שגיאות לפי API Contract, כולל תגובות ספק, יתרה שנגמרה, פלט פגום או שנקטע, כשל Validation ו־Rate Limit.
- Deadline משותף של 25 שניות, `maxDuration=30` ו־Client Timeout של 28 שניות, בהתאם לערכי ההתחלה בארכיטקטורה.
- `maxRetries: 0` וללא Retry אוטומטי בלקוח, ללא יצירה מחדש אחרי פסילת תוכן.
- טיפול בכשל HTTP שאינו JSON, ב־Timeout של הפלטפורמה ובאובדן רשת.
- שחרור מצב ההמתנה ושמירת הנושא ב־State כדי שהמשתמש יוכל לנסות שוב. הודעת הכשל בכרטיס היא „לא הצלחנו ליצור בדיחה. נסו שוב”.
- אימות הצגת תוצאה כטקסט בלבד, ללא HTML פעיל, ונגישות הטופס והודעות המצב: Label, Focus נראה ו־aria-live.

### תוצר מצופה

אותה יכולת יצירה עובדת גם לאחר שגיאות ותקלות מדומות, עם תגובות צפויות ואפשרות ניסיון נוסף באותו מסך.

### Definition of Done

- [ ] בדיקות מדומות מכסות פלט ריק, JSON פגום, Incomplete, Safety Refusal ושגיאות ספק 401, 429 ו־5xx, לפי המיפוי שבארכיטקטורה.
- [ ] ניתוק רשת, תגובת HTML במקום JSON וחריגה מה־Deadline אינם משאירים את המסך ב־loading ואינם מציגים פרטי תקלה פנימיים.
- [ ] אחרי כשל התיבה והלחצן חוזרים לשימוש, הנושא נשמר וניסיון נוסף יכול להצליח.
- [ ] ספירת הקריאות בבדיקות מאשרת שאין Retry סמוי או בקשה כפולה, ושכשל בבדיקת תוכן אינו מפעיל יצירה אוטומטית נוספת.
- [ ] טקסט שנראה כ־HTML מוצג כטקסט ואינו מתבצע בדפדפן.
- [ ] ניתן להשלים את הפעולה עם מקלדת, לזהות Focus ולקבל הודעות מצב באמצעות מנגנון aria-live, ללא הוספת Toast או מסך שגיאה.
- [ ] רענון מאפס נושא, בדיחה וכותרת („בדיחה יומית”); אין שמירתם ב־localStorage, ב־sessionStorage, ב־IndexedDB או בקובצי שרת.
- [ ] בדיקות Regression של מסלולי Milestone 2 ו־`npm run check` עוברים.

## Milestone 4 — פריסה מאובטחת ל־Production

**מטרה:** להפעיל את המוצר בכתובת ציבורית, עם הגנות התשתית ותהליך עדכון אוטומטי מ־GitHub.

**תלות:** אישור השלמת Milestone 3, חשבון Vercel (Hobby) וחשבון OpenAI עם יתרה. את חיבור החשבונות מבצע המשתמש, בהדרכה צעד אחר צעד.

### מה יש לממש

- חיבור ה־Repository ב־GitHub לפרויקט Vercel בתוכנית Hobby, עם `main` כ־Production Branch ופקודת Build הכוללת את `npm run check`.
- Configuration ב־Vercel: מפתח OpenAI נפרד ל־Production הנשמר רק בשירות, `OPENAI_MODEL` ו־`GENERATION_ENABLED`.
- ללא תשלום חדש: טעינה אוטומטית כבויה ב־OpenAI, ושימוש ביתרה הקיימת בלבד. אין שדרוג לתוכנית בתשלום, רכישת קרדיט או התחייבות כספית ללא אישור המשתמש.
- WAF Rate Limiting ל־POST /api/joke לפי ברירת המחדל התכנונית של 10 בקשות לדקה לפי IP, ו־Security Headers שנקבעו.
- Smoke Test ב־Production ואימות נוהל Rollback לגרסה קודמת. אין Database Migrations.

### תוצר מצופה

אתר פעיל ב־Production עם היכולת המלאה, הגנות התשתית ופריסה אוטומטית בכל דחיפה ל־main.

### Definition of Done

- [ ] גרסת Production נפרסת אוטומטית מ־main רק לאחר מעבר `npm run check`. מתועדים URL ומזהה הגרסה.
- [ ] מפתח Production נשמר רק ב־Vercel ואינו מופיע במחשב הפיתוח, ב־GitHub, ב־Client Bundle, בתגובות או בלוגים.
- [ ] טעינה אוטומטית של קרדיט כבויה ב־OpenAI, והתוכנית ב־Vercel היא Hobby.
- [ ] Smoke Test בקלט סינתטי מאשר מצב פתיחה, יצירה לפי נושא, יצירה כללית, החלפת בדיחה ודחיית נושא לא מתאים.
- [ ] כלל WAF חוסם חריגה לפני קריאה לספק; הלקוח מציג הודעת כשל מאושרת גם כאשר תגובת החסימה אינה JSON. בדיקת החריגה מבוקרת ואינה בדיקת עומס בלתי מוגבלת.
- [ ] Origin של אתר אחר נדחה; HTTPS ו־Security Headers פועלים ללא שבירת הטופס.
- [ ] `GENERATION_ENABLED=false` עוצר יצירה לאחר החלת התצורה בפריסה חדשה.
- [ ] מתועדים אופן Rollback ומגבלתו: החזרת קוד אינה משחזרת בהכרח WAF, Secrets או הגדרות OpenAI.

## Milestone 5 — התקנה ושימוש במובייל כ־PWA

**מטרה:** לאפשר למשתמש להתקין את האתר במכשיר תומך וליצור בדיחות מתוך ה־PWA, באותו מסך ובאותו עיצוב.

**תלות:** אישור השלמת Milestone 4 וכתובת Production ב־HTTPS, הנדרשת לבדיקת התקנה בטלפון.

### מה יש לממש

- Web App Manifest עם start_url ו־scope ל־`/`, מצב standalone, עברית ו־RTL, `name: "בדיחה לפי נושא"` ו־`short_name: "בדיחות"`.
- אייקון האפליקציה לפי DESIGN.md: 192×192, 512×512, גרסת maskable, apple-touch-icon ו־Favicon.
- התקנה באמצעות הדפדפן, ללא מסך התקנה או כפתור חדש באפליקציה, וללא Service Worker, Offline Cache או Background Sync.
- התאמות Responsive הנדרשות לשמירת טור תוכן קריא, שבירת טקסט טבעית ואזור מגע בגובה של לפחות 48px, בהתאם ל־DESIGN.md.

### תוצר מצופה

PWA שניתן להתקין ולפתוח במכשירי בדיקה תומכים מכתובת ה־Production, עם יצירת בדיחות עובדת בחיבור לאינטרנט.

### Definition of Done

- [ ] ה־Manifest והאייקונים נטענים בהצלחה, ללא קישורים שבורים.
- [ ] נבדקות התקנה ופתיחה ב־Chrome על Android וב־Safari על iOS, לפי המכשירים הזמינים למשתמש. מתועדים המכשיר, הדפדפן והתוצאה.
- [ ] פתיחה מהאייקון מציגה את מסך היצירה, וניתן להשלים יצירה לפי נושא ויצירה כללית דרך ה־Backend.
- [ ] אין גלילה אופקית או חיתוך של שדה, לחצן ובדיחה במידות מובייל שנבדקו; תוכן ארוך נשבר באופן קריא. במסך רחב הטור מוגבל ל־480px.
- [ ] אין הקשחה של העמוד ליחס Smartphone או מסגרת מכשיר דקורטיבית מתוך תמונת ה־Mockup.
- [ ] אין יצירה ללא רשת, אגירת בקשות או שימוש בבדיחה שמורה כתחליף. כשל רשת מטופל כב־Milestone 3; אין דרישה לטעינת האתר Offline.
- [ ] `npm run check` ו־Regression עוברים. בדיקה שלא בוצעה במכשיר יעד מסומנת כחסרה ואינה נחשבת הצלחה.

## Development Execution Rules — כללי ביצוע הפיתוח

ההנחיות הבאות מחייבות את ה־AI שיבצע את הפיתוח:

1. יש לפתח את ה־Milestones לפי הסדר שהוגדר במסמך, ולהשלים את ה־Definition of Done של כל אחד מהם לפני המעבר לבא אחריו.
2. לאחר השלמת כל Milestone, יש לעצור את הפיתוח ולהציג למשתמש את התוצר שהושלם, דרך להפעלתו, ואת תוצאות הבדיקות מול כל תנאי ב־Definition of Done.
3. יש להבחין בדיווח בין בדיקות עם Mocks, בדיקות AI חיות ובדיקות במכשירים אמיתיים. יש לסמן במפורש בדיקה שלא בוצעה, כשל או תלות חיצונית שלא הוסדרה. אבן דרך עם תנאי חובה חסר אינה נחשבת שלמה.
4. אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש. אישור להתחיל או להשלים את אבן הדרך הנוכחית אינו אישור להמשיך אוטומטית לבאה.
5. אין לעקוף תלות חסרה באמצעות שינוי פיצ'רים, החלפת שירותים או הקלה בדרישות התוכן והפרטיות. יש להציג את החסם ולבקש הבהרה כאשר נדרשת הכרעת משתמש.
6. חיבור Vercel ופריסה ציבורית מתבצעים רק במסגרת Milestone 4, לאחר אישור להתחילו. מרגע החיבור, כל דחיפה ל־main מעדכנת את האתר הציבורי.

מסמך זה מגדיר את תוכנית הפיתוח בלבד; עצם יצירתו אינה מתחילה את Milestone 1.

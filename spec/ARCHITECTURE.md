### תשתיות, Hosting, Deployment ו-Configuration
> ברירות מחדל מועדפות כאשר נדרשת פריסה לאינטרנט: Frontend בלבד ← GitHub Pages; Frontend + Backend ← Vercel; Frontend + Backend + Database ← Vercel + Supabase (PostgreSQL). בחר אחרת רק אם קיימת סיבה טכנית מהותית, והסבר אותה בקצרה.
>
> כאשר נבחר Supabase: הגדר שני פרויקטים נפרדים — אחד ל-Development (פיתוח ובדיקות) ואחד ל-Production (האתר החי והנתונים האמיתיים). המשתמש אינו מתכנת, ולכן אין להסתמך על Supabase מקומי או על התקנת Docker; הפיתוח והבדיקות נעשים מול פרויקט ה-Development בענן.

<ככל שרלוונטי: אופן אחסון הקוד ב-GitHub ותהליך ה-Build וה-Deployment האוטומטי. אם נדרש Database — אופן החיבור אליו, ניהול ה-Database Migrations ושמירת פרטי הגישה בצורה מאובטחת.>

<אם הוגדרו סביבות Development ו-Production נפרדות: איזו סביבה מחוברת לאיזה פרויקט והיכן נשמרים פרטי הגישה שלה (המחשב המקומי מחובר ל-Development בלבד); הנוהל להרצת Database Migrations — קודם על Development, ורק לאחר אישור המשתמש על Production, כולל מי מריץ ומתי; אילו הגדרות אינן עוברות ב-Migrations ויש להגדירן בנפרד בכל פרויקט; ומגבלות התוכנית העדכניות הרלוונטיות. הסר אם לא נדרש.>
